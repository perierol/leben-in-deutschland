# Evidence format

The summary and raw files follow the format already used in `docs/android-audit/evidence/F-04`, `F-05` and `F-09`, so `parse_reports.py compare` can read old and new summaries alike.

## Where files go

| Mode | Files | Location |
|---|---|---|
| Every run | `<run>.log`, `<run>-meta.txt`, `<run>-summary.txt`, `<run>-raw.txt` | session scratchpad |
| Every run | `<run>-summary.txt` (the same file) | `docs/android-audit/reports/verify/`: local and untracked, found by `android-pr` |
| `--finding F-xx --phase <p>` | `<p>-reports-summary.txt`, `<p>-raw.txt`, `<p>-verify.md` | `docs/android-audit/evidence/F-xx/` |

- Never overwrite. If `<p>-verify.md` exists, use `<p>-2-verify.md`, `<p>-3-…` for all three files of the run.
- The console log is never copied into the repository: it holds absolute paths and machine names. It stays in the scratchpad.
- Raw files are written by `parse_reports.py summarize --raw-out` to the scratchpad, then copied with `parse_reports.py sanitize`. Both replace the repository root with `<repo>` and the home directory with `~`.

## Run summary and fingerprint

`parse_reports.py summarize --meta … --out …` writes the summary itself. It starts with:

```
source: local android-verify
run: <run>
tier: <tier>
options: <options>
head: <full sha>
android_tree: clean | <16 hex>
fingerprint: <sha12>:<android_tree>
scope: android .github/workflows/android-ci.yml
command…: <each Gradle command>  (and exit.<step> for two-step runs)
```

These lines are followed by the counts and the `check` lines, including `check fingerprint`. `android-pr` treats a summary as current evidence only when `fingerprint.py`'s `is_current` accepts its `head` and `android_tree`. Summaries without these lines (everything before 2026-11-06, and the committed `evidence/F-xx` files) are **legacy**: readable, but never current.

## `<p>-reports-summary.txt`

Header lines (written by you), followed by the parser's output, unchanged:

```
# From Gradle reports of `<exact command>` (run from the repository root), <YYYY-MM-DD>
# Branch <branch>, commit <short sha><, plus uncommitted changes to: <paths>>
<parser summarize output, verbatim>
```

When a baseline was compared, append:
```
# Compared with <baseline path>
<parser compare output, verbatim>
```

## `<p>-verify.md`

```markdown
# F-xx · <PHASE> verification (<YYYY-MM-DD>)

> Generated by `/android-verify`. Local and untracked until you commit it.

- **Command:** `<exact command>`, tier `<tier>`
- **Code under test:** branch `<branch>` at `<short sha>` <"(clean)" or "plus uncommitted changes to: <paths>">
- **Environment:** JDK <version>, Gradle <version>, AGP <version> <; device <serial> / AVD <name> / API <n>>
- **Raw:** [`<p>-raw.txt`](<p>-raw.txt), [`<p>-reports-summary.txt`](<p>-reports-summary.txt). Console log kept local.
- **Phase check:** <PASS | FAIL>: <one line, e.g. "target `x` failed as expected at `:147` expected:<1> but was:<0>">

## Results
| Check | Result | Source |
|---|---|---|
| Build | Passed / Failed (exit n) | console |
| Unit tests | n tests in m classes, f failed, s skipped | JUnit XML |
| Lint | n warnings, e errors; changes against baseline | lint XML |
| <target test> | PASS / FAIL (assertion line) | JUnit XML |

## Failed
<test or task, first assertion line and frame, or "None">

## Not run
| Check | Reason |
|---|---|
| <check> | <reason> |

## Repository changes during the run
<"None", or the paths that changed and were not evidence files>
```

Leave interpretation (which production line causes a failure, or whether a fix is right) to `red-phase.md`/`green-phase.md`, written by whoever owns the fix. This file records only what ran and what the reports say.

## Result vocabulary

Use only these words. For build, tests and lint, `parse_reports.py summarize` prints them as `check <name>: <result>` lines. Copy those lines as they are.

| Result | Meaning |
|---|---|
| **Passed** | Executed in this run, reports fresh, 0 failures |
| **Passed (up to date, not executed in this run)** | Task `UP-TO-DATE`/`FROM-CACHE`; reports from an earlier execution with the same inputs |
| **Passed (vacuous: <reason>)** | Test returned without asserting (for example no content installed) |
| **Failed** | Executed and failed, or a safety check failed |
| **Not run** | Not executed, with the reason. Pending remote checks are *Not run yet* |
| **Needs verification** | Result depends on something the run cannot show (another JDK or Python version, a device, a console setting) |
